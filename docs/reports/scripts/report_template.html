1 · How the two approaches work

Both approaches read the same DXF, normalise it the same way and finish with the same build stages (walls → rooms → classification → validation → 3D). They differ in one step: how lines become walls, doors and windows. Approach 1 decides with geometry and rules. Approach 2 asks a trained model, SymPointV2, what every line is.

Approach 1: geometry, topology and rules (architectural_converter/)

IngestDXF (DWG via ODA); blocks expanded with full transforms
→
Preprocessunits from geometry, normalise to metres, adaptive tolerances, duplicates, strokes
→
Contextlayer names scored by keyword tables; every block given a role
→
Detectors5 wall detectors + doors, windows, columns, stairs
→
Resolvemerge candidates, weigh evidence, accept / review / reject
  • Wall detectors. Parallel line pairs at a plausible distance (the main one), closed thin polylines, wide polylines and MLINEs, wall-fill hatches, single centre lines (supported by layer and network), and layer evidence attached to geometric walls.
  • Doors come from a swing arc plus a leaf line, in blocks or loose geometry. Windows come from window symbols, glazing line groups inside a wall band, or lines that interrupt a wall band. Columns are compact closed or filled shapes. Stairs are runs of regularly spaced parallel treads.
  • Resolver. Each candidate gets a confidence from weighted evidence (thickness class, layer, hatch, dimension, topology). ACCEPTED at 0.68 or above, NEEDS_REVIEW at 0.45 or above, otherwise REJECTED. Every decision keeps its evidence and source DXF entities.
  • Strengths: handles any wall drawing style it has a detector for, and works without layer names (benchmark drawing 09). Weaknesses: furniture drawn as parallel lines can pair into walls, and kitchen counters trigger missing-wall guesses.

Approach 2: SymPointV2 labels (sympoint_converter/)

Ingest + preprocessshared with approach 1
→
Tilesdrawing cut into 20 m tiles (4 m overlap), sent to the GPU service
→
SymPointV2a class for every line, arc and circle (35 FloorPlanCAD classes)
→
Rules on labelslabel consensus by entity, block and layer
→
extract.pywalls, doors, windows, columns, stairs built from the labels
  • The model was trained on FloorPlanCAD (crops of apartment and office plans). It answers line by line and tile by tile, so its answer is locally noisy. It runs in a local GPU service, and answers are cached per drawing.
  • Building from labels. Two parallel wall-labelled lines 4–90 cm apart form a wall. Short closed pieces become columns or wall nibs. Door-labelled clusters split by their swing arcs become doors. Window, bay window and curtain-wall labels become windows along the nearest wall. Stair-labelled lines become flights, and railing lines become balcony parapets.
  • The rules ("guidelines"). Label consensus: one entity is one object, a block inserted many times is one kind of object, and a layer holds one kind of thing. Where the model is silent, the layer name gives a weak label. Room names: a room holding two kinds of name is missing a wall. Wall structure: wall groups that enclose nothing and host no door or window are rejected. Enclosed floors: an area mostly surrounded by building gets a floor.
  • Strengths: tells furniture from walls well, so it adds no false walls along counters and wardrobes. Weaknesses: anything drawn unlike FloorPlanCAD (single-line walls, wide polylines, real-world glazing) goes unlabelled, and the rules fill those gaps mostly from layer names.

Proposed hybrid: approach 2 with an approach-1 fallback (experiment)

Metrics
  • Walls: length-based. Centre lines are sampled every 5 cm; a sample is correct within max(0.6 × thickness, 8 cm) of a reference axis running the same direction. Precision = correct share of detected length, recall = found share of reference length.
  • Rooms: matched at intersection-over-union ≥ 0.5. Doors, windows, columns: matched by centre distance (doors and windows within max(half the width, 0.3 m)).
  • Fixes per drawing: false and missed walls, rooms, doors, windows and columns added up; the manual corrections a user would make.
  • Items marked NEEDS_REVIEW count as detected.
  • Line-level label accuracy (section 4.1): share of each class's line length the model labelled correctly, before any rule runs. The true class comes from the drawing's layer.
Validation of the pipeline used here

The GPU run saved the model's raw answer for every drawing. Rebuilding approach 2 from those answers on a CPU-only machine reproduced the GPU report's scores exactly on all 13 benchmark drawings. All variants in this report (rules off, no layer names, fallback) start from those same saved answers.

6 · What is missing, ranked by payoff

  1. Approach-1 fallback for lines the model leaves unlabelled. The largest measured gain: room recall 0.83 → 0.99 without layer names, apartment windows 0.30 → 0.95, fixes per drawing 5.0 → 2.6. It belongs in sympoint_converter/reasoning/.
  2. Windows. Wall bands are built straight through window openings, and real glazing lines mostly get no label. A gap in a wall band with glazing-like lines inside should become a window, whatever the label.
  3. Duplicate doors in approach 2. 29 near-duplicate pairs on one permit-set floor. Doors closer than 0.6 m on the same wall should merge.
  4. Single-line and wide-polyline walls. The model doesn't recognise them; approach 1 handles both perfectly. Route these drawing styles to approach 1's wall detectors.
  5. Non-architectural linework labelled wall. Room-area outlines, roads and sections on the permit set. Area-identification and site layers need a veto, and wall groups that enclose nothing should be rejected in more cases.
  6. Columns in approach 2. SymPointV2 has no column class; benchmark drawing 10 loses all columns.
  7. Balconies as rooms in approach 2. Balcony outlines labelled wall don't close into rooms (6 missing on the apartment).
  8. Approach 1 bugs on the permit set. Rooms created twice on stacked storeys; site and plot outlines become rooms and walls.
  9. Room types. Most apartment rooms are typed only as "room": the drawing has no room names, and geometry-only typing knows just corridor and service room.
  10. Reference answers for real drawings. Walls and rooms on both real drawings, and doors on the permit set, are still unscored. Every number on real drawings beyond doors and windows is a check, not a measurement.

7 · Limits of this report

  1. Line-level truth comes from layer names. Layers that mix content (frames on a wall layer, for example) blur the numbers by a few percent.
  2. The apartment's door and window truth comes from the same layers approach 1 reads, so approach 1's 1.00 there confirms consistency rather than independent accuracy.
  3. Permit-set door accuracy is unknown: its doors aren't drawn as simple swing arcs, so they couldn't be counted reliably from the DXF.
  4. The 13 benchmark drawings are synthetic and were used to develop approach 1's rules, so approach 1's near-perfect scores there don't carry over to real drawings.
  5. The approach-1 fallback was tested as a label-level experiment, not as production code; its real-drawing gain is measured on one drawing.
  6. The first benchmark (section 3) used invented error rates. Section 4.3 shows how far they were from the real model.

A.2 How to reproduce

On a machine with the SymPointV2 service (branch claude/practical-planck-ugw5wn):

python -m sympoint_converter label <drawing.dxf> -o gpu_out/ for every drawing (saves *.sympoint.response.json), then python -m sympoint_converter compare --benchmark -o gpu_out/.

Without a GPU, any build can be repeated from a saved answer: python -m sympoint_converter build <drawing.dxf> --response <name>.sympoint.response.json -o out/ (add --no-reasoning to switch the rules off).
